# 通信障害の調査用ログ

[READMEへ戻る](../README.md)

[`scripts/zenoh-capture.sh`](../scripts/zenoh-capture.sh)で、Zenohログ・TCP接続・通信量・PC負荷・pingをまとめて保存する。中央・車載・制御PCで同時に記録すると、異常発生時刻を比較できる。

## 実行方法

Ubuntu 22.04上で、リポジトリのディレクトリから通常ユーザーで実行する。必要なsudo認証はスクリプト内で行う。

```bash
./scripts/zenoh-capture.sh
```

- 記録時間：3600秒（1時間）
- 保存先：`~/zenoh-logs/zenoh-<ホスト名>-<UTC日時>-<識別子>/`
- 終了方法：時間経過による自動終了、または`Ctrl+C`

実行中はターミナルを開いたままにする。通常終了・Ctrl+C時には、生成したログフォルダの所有者を実行ユーザーへ戻す。電源断や`kill -9`では終了処理は実行されない。

時間・保存先を指定する場合：

```bash
# 10分間記録
./scripts/zenoh-capture.sh 600

# 1時間記録し、保存先を指定
./scripts/zenoh-capture.sh 3600 "$HOME/zenoh-logs"
```

記録時間は1〜86400秒で指定する。スクリプトはリポジトリ内から直接実行でき、ログ取得のための`make update`は不要。

## 記録内容

| ファイル | 内容 |
|---|---|
| `metadata.txt` | 開始時の時刻同期、IP・経路、router状態、パッケージ情報 |
| `router.log` | 開始5分前からのrouterログと、記録中の追加ログ |
| `tcp.log` | TCP 7447の接続、送受信キュー、RTT、再送情報。約1秒間隔 |
| `network.log` | 各NICの累積送受信量・drop数。約1秒間隔 |
| `process.log` | routerのプロセス情報、CPU累積値、システム負荷。約5秒間隔 |
| `ping-<IP>.log` | 対象PCへのping。約1秒間隔 |
| 設定ファイル | 読み取り可能な配置済み設定のコピー |

時刻は原則UTCで記録する。日本時間はUTCに9時間加算する。pingの`-D`時刻はUNIX時刻。

NICの通信量には、LiDARなどZenoh以外の通信も含まれる。TCP再送数やNICのカウンタは累積値なので、記録中の増分で判断する。`ps`のCPU使用率はプロセス起動後の平均値。

各継続ログは32MiBごとに切り替え、現行ファイルと過去15世代（合計16ファイル）を保存する。継続ログの合計は1回あたり約3GiBが目安で、別途メタデータ・設定コピーが加わる。上限を超えると古い世代は削除される。過去の実行フォルダは自動削除しない。

## ping対象の設定

現在のスクリプトは次のIP構成を前提とする。

| 実行PCのIP | ping対象 |
|---|---|
| `192.168.1.70`（中央） | `192.168.20.73`、`192.168.20.119` |
| `192.168.20.73`（車載） | `192.168.1.70`、`192.168.20.119` |
| 上記以外（制御PCを想定） | `192.168.1.70`、`192.168.20.73` |

**ping対象は`deployment.env`から自動取得しない。** 別のIP構成で使う場合は、スクリプト末尾のIP判定と`targets`を変更する。

## 障害を再現するとき

1. 各PCの時刻同期を確認し、関係するPCでログ取得を開始する。
2. 機体の安全を確保して実際のプログラムを動かす。
3. ノード起動・終了、RVizでの購読開始、異常発生などの操作・発生時刻をメモする。
4. 異常発生後、安全上支障がなければ再起動前に1〜2分記録を続ける。
5. `Ctrl+C`で取得を終了し、各PCの出力フォルダと操作メモを保存する。

まず実際のプログラムで記録し、特定の通信が原因として疑われた段階で、テスト用プログラムによる比較を行う。

スクリプトはrouterの再起動・設定変更やROSのTopic配信・Action Goal送信を行わない。疎通確認用のpingは送信する。スクリプトをCtrl+Cで終了しても、routerやROSノードは停止しない。

Actionサーバの探索状態、Rajant内部の無線状態、パケットキャプチャ、ROSノードの標準出力は取得対象外。ROSノード側に表示されたエラーは、別途ログや画面を保存する。TCP接続が維持されていても、ROS通信の正常性を保証するものではない。

## ログを読めない場合

終了後もroot所有のままの場合は、通常ユーザーのターミナルで、実際の出力フォルダを指定して所有者を戻す。

```bash
# 下のパスを、実際の出力フォルダに置き換える
sudo chown -R "$(id -u):$(id -g)" "$HOME/zenoh-logs/zenoh-<ホスト名>-<UTC日時>-<識別子>"
```

旧版で親フォルダ`~/zenoh-logs`がroot所有になっている場合は、親フォルダ自体も修正する。

```bash
sudo chown "$(id -u):$(id -g)" "$HOME/zenoh-logs"
```

`router.log`が空でも、対象期間にログ出力がなければ正常。権限不足のメッセージがある場合は、sudo認証を伴う実行になっているか確認する。
